## 一、研究问题与任务定义

本调研围绕两个断点展开：**被引文献是否真实存在、书目信息是否准确**，以及**被引文献中的内容是否支持正文中的论断**。

### 1.1 文献真实性校验（书目核验）

输入是一条书目记录（通常为 BibTeX 条目或参考文献字符串，含标题、作者、年份、发表场所、DOI 等字段），输出是它与真实世界作品的对应关系判定，含三层：能否对应到真实作品、各字段是否与作品实际属性一致、不一致属哪类。

典型错误分三层：**身份层错误**指作品不存在——完全虚构、拼接真实作品片段的"嵌合"标题、大模型按领域惯例生成的高可信度虚构条目；**字段层错误**指作品真实而字段被换——作者名单替换或截断、发表场所不存在或错误、预印本标为正式发表版本、DOI 指向另一篇作品；**时间层错误**指年份超出合理范围或与实际不符。HALLMARK 将 14 种类型按难度分 3 层：易层（伪造 DOI、不存在的场所、占位作者、未来日期）单次 API 查询即可识别，中层（嵌合标题、错误场所、作者错配、预印本当正式版、混合伪造、合并引用、作者列表不全）需跨字段核对，难层（近似标题、貌似可信的伪造）需深度核验或语义推理^[1]^。

其边界是**不判断论文的科研结论是否正确**，也**不判断引用者是否正确理解了被引文献**。GhostCite 只核对标题可追踪性，检测到的是保守下界，会漏掉"高度貌似真实"的幻觉^[2]^。

### 1.2 证据对齐（支持关系判断）

输入是引用上下文（施引文献中讨论被引文献的句子或片段）与被引内容，输出是支持关系标签及其证据位置。支持关系通常分支持、部分支持、不支持（反驳）、证据不足四类，细分各异：Citation-Integrity 用 ACCURATE / NOT_ACCURATE / IRRELEVANT 三分类，NOT_ACCURATE 再分 CONTRADICT、NOT_SUBSTANTIATE、MISQUOTE、OVERSIMPLIFY、INDIRECT、ETIQUETTE 等^[3]^；SemanticCite 用支持 / 部分支持 / 不支持 / 不确定四分类并输出证据与理由^[4]^；RefVerifier 用 Supported / Partially Supported / Not Supported / NEI 四分类^[5]^。

错误类型同样分层。**检索层错误**指证据句未被找到——Citation-Integrity 上 BM25+MonoT5 的 Recall@20 仅 0.53–0.55，约一半人工标注证据句检索不到^[3]^。**定位层错误**指找到段落但未精确到句子或表格。**判断层错误**指证据正确但支持关系判错，最困难的是"部分支持"：论断被放大强度、忽略条件或把相关性当因果。SciCiteVal 用受控构造将其细分为反转语义极性、篡改数值、加入原文未提及的信息、替换术语为怪诞短语、改变核心概念五类，模型识别"加入未提及信息"与"怪诞短语"的准确率仅 0.35 和 0.13^[6]^。

### 1.3 两个任务的联系与区别

两任务共享"找到可靠身份记录"的底层能力，但评价对象不同，**不能相互替代或合并结果**。

第一，**证据来源不同**：书目核验依赖结构化数据库（CrossRef、OpenAlex、DBLP、DataCite、Semantic Scholar），证据字段级、可确定性比对；证据对齐依赖被引全文，须经检索与语义判断。

第二，**失败模式不同**。书目核验的风险主要是**假阳性**——真实作品尚未被索引、出版社反爬使 DOI 解析返回 202/403、解析错误把标题片段当成作者，都会把真实引用误报为幻觉；Phantom References 复核后坦言"手工检查的 flag 中多数不是幻觉"，并把"未发表作品与尚未被索引的作品无法区分"列为结构性局限^[7]^。证据对齐的风险则是**假阴性**：检索不到证据时系统倾向输出"不支持"，实为检索失败。

第三，**覆盖链条位置不同**：书目核验是证据对齐的前置条件，但前者通过**不蕴含**后者。HALLMARK 的实验即一例：267 篇 NeurIPS workshop 投稿的 5,043 条去重引用经级联核验，未发现任何伪造作品，但第二阶段维持的 324 条 flag 中 59.0% 属于"真实作品被描述错误"^[1]^。

## 二、代表性方法与技术路线

### 2.1 文献信息解析

输入形态决定误差下界：BibTeX 输入解析相对确定，PDF 输入下参考文献区抽取最嘈杂——Phantom References 称之为"全流程最嘈杂的一步"，指出字段合并与切分错误、标题截断是假阳性主要来源，建议会议投稿时直接收集 .bib 源以跳过该环节^[7]^。

现有工作走三条路线。**规则与专用模型**：CiteAudit 用 Nougat/PyMuPDF 解析版面，Qwen3-VL-235B 抽取结构化字段^[8]^；HalluCiteChecker 用 Docling CPU 解析加 DeLFT 序列标注（18 个实体标签），避开生成式模型以换取离线与低成本^[9]^；GhostCite 以 GROBID 为主解析器，失败时回退到 LLM 按 JSON schema 重解析^[2]^。**视觉-语言模型**：CiteTracer 用 DeepSeek-OCR 2 提议高召回引用块，再由 Parser Agent 对裁剪块图像与 OCR 文本二次复核；消融显示 LLM 重解析对作者字段准确率贡献最大（85.6→98.2），加入页面图像后标题与标识符进一步提升^[10]^。

共同结论是**解析错误会被下游当成核验失败**：标题截断即检索不到，系统会把解析问题报成"文献不存在"。近年工作因此普遍设置"解析兜底"，如 GhostCite 在四级级联末端加入 LLM 重解析，前提是解析错误污染了查询串^[2]^。

### 2.2 文献检索与实体匹配

检索把待核验记录映射到数据库中的身份记录，关键分歧是**匹配键**与**多源策略**。

匹配键方面，HalluCiteChecker 论证了只用标题的合理性：作者名常缩写或截断为 et al.，场所名常缩写，DOI 与 URL 覆盖率不一致、落地页各异，而标题是唯一在所有引用格式中都完整出现的字段^[9]^。但只用标题有系统性盲区：作者、场所、年份错配等字段层错误完全不可见，这正是 CiteTracer 把裁决下沉到字段级的原因^[10]^。

多源策略方面，CiteTracer 并行查询 8 个学术连接器（arXiv、DBLP、CrossRef、Semantic Scholar、OpenAlex、ACL Anthology、Europe PMC、PubMed），每源取 top-5^[10]^；CiteAudit 用"网页检索 + Scholar 高精度低频爬取"两级结构，证据不足时才升级^[8]^；RefChecker 在五个来源间保留冲突证据，"不把任何单一数据库当作绝对真值"^[7,11]^。HALLMARK 的级联把规则工具与 LLM 组合：第一阶段用 bibtex-updater 查询六个来源，只把无法确定的条目交给第二阶段的 LLM 智能体^[1]^。

**多源检索的收益与代价并存**。CiteTracer 把"检索成本与可扩展性"列为首要局限：并行调用 8 个连接器开销大，高并发下限流，反而降低证据覆盖率^[10]^。HALLMARK 用对照实验量化了这一点：智能体化检索换来召回提升，假阳性率却约为纯规则工具的 9 倍；底层模型换成另一家后指标差异不超过 5 个百分点——问题出在"任一来源未命中即报警"的策略，而非模型能力^[1]^。

### 2.3 字段级核验

字段级核验把"记录是否真实"拆成可独立回答的子问题，各有证据来源与判定规则。HALLMARK 每条目对应六个子测试——DOI 能否解析、标题是否存在、作者是否一致、场所是否正确、字段是否完整、跨库是否一致^[1]^。CiteTracer 的字段匹配器先做确定性归一化匹配（大小写折叠、标点、DOI 规范化、页码区间、作者名归一），全字段匹配早退为"确定性真实"，残余情形由匹配智能体输出逐字段残差状态（可归一化变体 / 候选缺失 / 引用缺失 / 真冲突）^[10]^。

子测试的价值在于**诊断**：它说明"可疑"属哪类。HALLMARK 据此把系统失效归纳为三种模式：检索换召回但推高假阳性、低流行率下精确率崩塌、时间鲁棒性不足（2024–2025 年新文献上，12 个 LLM 中 8 个严重过报，最高假阳性率约 0.89）^[1]^。

### 2.4 证据检索与重排

对齐的第一步是在全文中定位相关片段。

Citation-Integrity 用 BM25 取 top-60 句、MonoT5 重排取 top-k（k=5/10/20），并比较三种查询：直接用引用句、人工标注语境、完整语境^[3]^。SemanticCite 用 ChromaDB 稠密向量取 top-15 与 BM25 稀疏检索取 top-15，去重合并后用 FlashRank 交叉编码器重排取 top-3^[4]^。RefVerifier 把被引全文切成重叠的三句窗口，以 all-MiniLM-L6-v2 与 BM25 分别排序后经 RRF 融合，再用 bge-reranker-v2-m3 重排^[5]^。

一个反复出现的经验是**重排的收益有限，检索召回的瓶颈更硬**。Citation-Integrity 报告 Recall@20 仅 0.53–0.55、MRR 0.31–0.33，不同证据策略间差异不显著^[3]^。RefVerifier 在其全文设置下 top-10 池命中率 75%、top-3 仅 52%，加强重排后提升到 0.69^[5]^。

更根本的约束是**全文获取率**。RefVerifier 报告开放获取全文解析率仅 57.6%（571/992），学科差异极大：计算机与物理 86%、数学 52%、生物医学 35%；未解析的 421 条中 54.9% 全网无免费版^[5]^。端到端系统的效果上限先被开放获取版图限定；SemanticCite 同样把"全文不可得时回退到摘要"称为"达到更高准确率的主要障碍"^[4]^。

### 2.5 支持关系判断

**微调专用模型**。Citation-Integrity 把 MultiVerS 迁移到引用场景，用 Longformer 编码被引全文，同时预测文档级标签与句子级证据，在 3,063 条真实引用上取得 0.59 micro-F1 / 0.52 macro-F1^[3,12]^。SemanticCite 用 QLoRA 微调 Qwen3 1.7B/4B/8B，4B 模型在 112 例测试集上取得 66.36% 标准准确率、83.64% 加权准确率^[4]^。

**提示式大模型判断**。Citation-Integrity 对照实验中，GPT-4 以 4 例演示取得 0.65 micro-F1 / 0.45 macro-F1，micro-F1 高于微调模型，但 NOT_ACCURATE 类的 F1 仅 0.09——大模型倾向把错误引用判为正确^[3]^。SciCiteVal 上，六个开源 LLM 的 zero-shot 准确率在 0.62–0.79 之间，少样本示例提高 Correct/Unrelated 的判别却降低 Incorrect 的识别^[6]^。RefVerifier 的对比显示模型规模与推理预算影响可观：nano 低预算宽松准确率 0.59，terra 中预算 0.73，550B 开源模型 0.64^[5]^。

**证据驱动的推理与不确定性表达**。SemanticCite 把引用句改写为"事实中心"断言后再判断，输出证据片段、相关性分数与理由^[4]^。RefVerifier 按论断类型（背景、结果、方法等七类）套用不同判定标准，对冲语言（hedge）另行处理，避免把"可能相关"判成"支持"^[5]^。

**任务边界与能力现状**。作为整体阅读的补充，科学事实核验的任务体系、资源与方法可参考综述^[13]^；引用核验工具在抽取、书目覆盖、判定与使用各环节的能力边界，可参考针对现有工具的评估^[14]^。两者共同提示：**现有方法尚不足以安全部署，工具未检索到不能作为作品不存在的证明。**

**标签体系存在分歧**。Citation-Integrity 承认公开数据集的标签定义与四类裁决并不完全对应，如把直接矛盾与过度简化、弱论证混在同一类，保守系统因此被准确率惩罚^[5]^。HALLMARK 用敏感性实验说明分类定义如何改变结论：把四种"真实论文但元数据写错"的类型折叠或计为假阳性后（占正类 26.1%），20 个工具中 13–16 个换位，test_public 第一名从级联变为 bibtex-updater^[1]^。**"什么算引用幻觉"这一前提本身尚未达成共识**。

## 三、数据集与评价方法

### 3.1 数据集按评价对象分类

**评价书目真实性的数据集**：HALLMARK（2,526 条 BibTeX，14 类错误 × 3 难度层，公开 2,072、隐藏 454）；CiteAudit（9,442 条 = 生成 6,086 + 真实 3,356，人工双标）；CiteTracer（合成 2,450 + BIOMED-1K 1,000 + 真实场景 957）；GhostCite 档案语料（2,199,409 条引用，人工复核 2,530 条 flag）；Phantom References 审计语料（2,614,992 条引用，48,095 篇论文）。

**评价证据定位与支持关系的数据集**：Citation-Integrity（3,063 条真实引用、100 篇被引论文，ACCURATE / NOT_ACCURATE / IRRELEVANT，按被引论文 70/10/20 划分）；SciCiteVal（1,034 条，Correct / Incorrect / Unrelated 及五个 Incorrect 细类）；SemanticCite-Dataset（1,111 条，8 学科，四分类）；CL-SciSumm（引用句到片段的**对齐**，40 个手工标注与 1,000 个自动标注集合需分开对待）；RefVerifier 分阶段评测集。

**评价生成式引用忠实性的数据集**：CiteCheck 2025（中文 RAG 场景，训练 9,796 / 开发 1,000 / 测试 1,000，二值标签）^[15]^；ALCE（ASQA / QAMPARI / ELI5 各 1,000 条，评价生成答案中的 citation precision/recall）；AttributionBench（ID 13,322 / 1,198 / 1,610，OOD 1,686，二分类）；RAGTruth（17,790 条生成回答，词级与片段级幻觉标注）。

**基础事实核验资源**：SciFact（1,409 条 claim、5,183 篇摘要，SUPPORTS / REFUTES / NOINFO，测试标签不公开）^[16]^；SciFact-Open（279 条 claim、约 50 万篇摘要，池化标注）^[17]^；MiniCheck 的 LLM-AggreFact（11 个数据集、约 29K 样本，仅允许作评价基准，不可用于预训练或微调）^[18]^。

### 3.2 划分方式与泄漏风险

划分陷阱直接决定结果是否可信。

**按来源论文分组**。Citation-Integrity 按被引论文做 70/10/20 划分，避免同一被引论文的相似内容跨训练与测试集泄漏；复现必须保留该分组，否则模型会记住被引论文而非学会判断^[3]^。同理，SciCiteVal 的成对正确/错误版本来自同一条 QASA 样本，须按来源分组划分^[6]^。

**标签与历史预测字段**。CiteAudit 的 benchmark.json 同时含 GT 与 Predict 字段（真实标签与历史预测），只能用于评分或核对，**不能送入待评价模型或检索过程**^[8]^。HALLMARK 的公开数据含 label、hallucination_type、difficulty_tier、explanation、subtests 等字段，其中 subtests 是逐条目的子测试金标准，作为输入即构成泄漏^[1]^。

**合成样本与自然错误的区分**。SciCiteVal 的 Incorrect 部分由标注者对 QASA 样本受控扭曲合成，不是自然错引；SemanticCite 真值由 GPT-4.1 生成而非独立专家；HALLMARK 多数幻觉条目由系统扰动或 LLM 生成。报告时须明确"在什么构造条件下测得"，避免与自然错误上的结果比较。

### 3.3 评价指标

**虚假文献检测**应把"虚假引用"设为正类，使 Recall 对应虚假引用检出率。HALLMARK 主指标包括检测率（Detection Rate，幻觉类召回）、假阳性率（FPR，真实条目被误报的比例）、幻觉类 F1、难度层加权 F1（仅召回按层加权，假阳性权重恒为 1）、MCC、ECE（校准误差）、覆盖率与平均 API 调用数^[1]^。

**允许拒答的系统必须报告覆盖率**：HALLMARK 的保守模式把 UNCERTAIN 排除在分类指标外，激进模式将其与缺失预测按 HALLMARKED@0.55 处理，两模式差值量化了"数据库索引滞后"的代价^[1]^。RefChecker 同样把基础设施失败值（api_failure、processing_failed 等）排除在幻觉计数外，UNCERTAIN 留在审计日志但不计入阳性^[7,11]^。

**证据定位与支持关系判断**使用 Recall@k、MRR、命中率@k 与分类的 P/R/F1。两点需注意：Citation-Integrity 的检索指标定义为"标注证据句中落入 top-k 的比例"^[3]^；RefVerifier 的宽松/严格映射把"部分支持"分别归入"支持"或"NEI"，同一系统两种映射下的准确率差异可达 30 个百分点（如 Citation-Integrity 上 0.72 对 0.32）^[5]^。

**不能直接比较的指标**。SemanticCite 的 weighted accuracy 是对序数标签加权的自定义指标（最大权重 3），**不等于普通准确率**，不能与其他论文的 Accuracy 并列^[4]^。ALCE 的 citation recall 与检索 Recall@k 不同：前者按 statement 计算，要求引用非空且 NLI(concat(引用), statement)=1^[19]^。AttributionBench 统一为二分类 macro-F1，与三分类任务的准确率不可比^[20]^。

**不应合并的数据集**。"书目不存在""书目信息有误""证据无关""证据不足""证据明确反驳"含义不同，统一为"假"会改变原任务且结果难以解释；HALLMARK 的敏感性实验即该结论的量化证据^[1]^。

## 四、开源资源与复现可行性

### 4.1 资源分级

按是否具备完整复现条件分级，而非是否有 GitHub 页面。

**完整实现与数据**：HALLMARK（数据、全部基线、评测代码与逐样本参考结果；MIT；无 GPU 需求；纯 Python，依赖 bibtexparser、requests、httpx、rapidfuzz）；Citation-Integrity（数据、改自 MultiVerS 的训练与推理代码、模型下载说明；MIT；需 GPU）；CiteTracer（数据、8 连接器、judge-only 复现脚本、评测脚本与单元测试；MIT；云 API 依赖）；CiteAudit（benchmark.json 含 9,442 条带标签引用与运行脚本；需三套 API key）；GhostCite 的 CiteVerifier（工具源码与文档站；MIT）。

**评价材料包**：RefVerifier（输入、人工标签、运行输出、评分说明；可复核已有结果，但**不能据此确认完整应用源码已公开**）；SciCiteVal（数据、构造说明与实验结果；未核实为完整端到端系统）。

**只有论文或部分资源**：DeepSciVerify（仅核实论文，未核实官方实现）；CiteCheck 2026（arXiv:2605.27700，仅论文，官方代码与基准下载入口未核实——它与 2025 年 `xzy-xzy/CiteCheck` 不是同一项目）；SCINLP（仓库主要展示数据构造流水线，成品标注数据下载入口未核实）。

**工程参考，非论文基准**：EvidenceClaw（PDF 处理、文献检索、证据编号、逐段审查、规则验证与报告生成；案例与 mock 模式不能替代独立标注测试集）；DeepScientist（科研工作流编排，不宜代替核心核验模型）。

### 4.2 复现障碍与成本

**硬件**。本机 GPU 为 NVIDIA MX570（2 GB 显存），不足以训练 MultiVerS 级模型或本地部署 7B 以上模型。故复现对象应选**无 GPU 需求**的工作；需训练的路线（Citation-Integrity 的 MultiVerS 微调、SemanticCite 的 QLoRA 微调、CiteCheck 的 LoRA 微调）只能改用预训练权重推理或本地小模型，并标注为"适配实验"。

**外部服务依赖与调用成本**。CiteAudit 全量运行需约 8,000–9,000 次 SerpApi 调用并依赖 Gemini 与 OpenAI，成本需提前核算。GhostCite 依赖 DBLP 本地库与 ScrapingDog 代理。CiteTracer 并行调用 8 个连接器，高并发下触发限流。HALLMARK 免费基线依赖 CrossRef、DBLP、DataCite、OpenAlex、Semantic Scholar 与 OpenReview，其中 Semantic Scholar 无 API key 时被限流（HTTP 429），OpenReview 的 API 在部分网络环境下返回 403。

**复现障碍的可测性**。HALLMARK 仓库的 bibtex-check 在超过 10% 的条目存在"未完成的来源查询"时以退出码 5 结束，包装层抛出 `SourceOutageError` 拒绝评分，理由是"一个从未应答的来源不能作为引用不存在的证据"。因此**复现者必须先报告来源可达性**，否则数字可能只是网络状况的测量。

**许可差异**。同一项目的代码、数据、模型许可可能不同：SemanticCite 代码为 MIT 而数据为 CC-BY-NC 4.0；RefVerifier 复现包为 MIT 而 CiteWorth 派生文件为 CC BY-NC 4.0、SciFact 为 CC BY-NC 2.0；LLM-AggreFact 仅允许作评价基准，不可用于预训练或微调；SciFact-Open 与 AttributionBench 的仓库未声明许可证。

## 五、拟开展的复现方案

### 5.1 选择与理由

本项目选 **HALLMARK** 为主复现对象，深入**书目真实性核验**路线。理由有三：无 GPU 需求、依赖为纯 Python 包，在本机条件下可完整运行而非降级运行；仓库发布全部基线的逐样本预测与参考指标，"复现是否成功"可逐项核对，不必与论文正文数字比；14 类错误 × 3 难度层的细粒度标注为分析性实验留下空间——本项目要回答的不是"能否复现一个分数"，而是"方法何时有效、何时失效"。

调研报告同时覆盖证据对齐路线（Citation-Integrity、SemanticCite、SciCiteVal、RefVerifier），实验部分明确边界：本项目**不声称实现了自动证据检索**，也不声称完成了论断与原文证据的语义对齐，即落实任务边界中"只完成书目信息核验"的要求。

### 5.2 复现范围与数据

采用 HALLMARK v1.2.4（构建日期 2026-10-15）的公开划分：`dev_public` 1,119 条（504 真实 / 615 幻觉）、`test_public` 831 条（307 / 524），合计 1,950 条；`test_hidden`（454 条）不公开，不参与评测。评测基准年份固定为 2026，保证未来日期判定的可重复性。

基线包括：常量参照（全判真实、全判幻觉、固定种子随机）、DOI 存在性启发式、仅 DOI 解析（含与不含预筛两版）、HalluCiteChecker 标题匹配移植版、CheckIfExist 三来源级联移植版、数据库优先级联（bibtex-check 第一阶段 + LLM 诊断第二阶段）。

### 5.3 核心问题

四个可检验问题各配一组对照实验：

**Q1（复现一致性）**：同一划分与评分脚本下，确定性基线的指标能否与仓库参考结果一致？不一致时，差异来自方法、来源可用性还是环境？

**Q2（子测试诊断能力）**：六个子测试各自对哪类错误有信号？当作独立检测器时，精确率、召回率与覆盖率如何？子测试需在真实来源上重新推导时，与标注结果的一致率是多少，即标注本身的可复现性上界在哪里？

**Q3（单阶段与级联的权衡）**：仅 DOI 解析、标题匹配、多来源级联三者在检测率、假阳性率与 API 成本上的关系如何？级联换来的召回提升是否值得其代价？

**Q4（不确定性与泛化）**：拒答条目在不同评分立场下的影响有多大？在真实世界来源与 LLM 生成来源的样本上，同一方法的检出率是否一致？

### 5.4 预期与评价协议

协议如下。**公平比较**：所有基线用同一划分与评分脚本（上游 `hallmark.evaluation.metrics.evaluate`），除待验证因素外一致。**防止泄漏**：只向基线传递 `BlindEntry`（剥离标签、错误类型、子测试金标准与 URL），评分阶段才用真值，不得用数据文件中的历史预测。**保留原始结果**：逐样本预测、证据位置、评价脚本与日志全部保存，汇总可重算；在线检索记录日期与来源可用性。**区分证据范围**：获取失败时记录状态，不直接输出"原文不支持"或"文献不存在"。**如实报告随机性与成本**：记录随机种子与调用次数，随机性实验说明重复情况。

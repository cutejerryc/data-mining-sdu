## 摘要

大语言模型进入学术写作流程后，"引用是否存在"由可穷尽的检查项变成规模化风险：13 个主流模型的引用幻觉率从 14.23% 到 94.93% 不等，已通过同行评审的论文中约 5% 的 NeurIPS 2025 与 USENIX Security 2025 论文含两条以上严格定义下的伪造引用。工具与基准随之涌现，但前置问题未被回答：**它们本身在多大程度上可复现？**

本文以 HALLMARK 基准（arXiv:2607.18360，v1.2.4）为对象，复现其确定性基线与数据库优先级联并开展四项分析性实验。主要发现：（1）**确定性基线可被精确复现**：`doi_only` 在 `dev_public` 上检出率、假阳性率、F1、Tier 加权 F1、MCC、AUROC、ECE 七项指标与发布值**逐项一致**（绝对差 0.0000），`test_public` 上仅 AUROC 与 ECE 差 0.0009 与 0.0004。（2）**标注与实测层面的子测试落差显著**：以发布标注为检测器时"任一子测试失败"在 `test_public` 上 F1 = 0.971，而 180 条分层子样本上重新推导的一致率从 0.2266 到 0.9667 不等，实时检测器假阳性率高达 0.9848。（3）**难度层比错误类型更具预测力**：各方法在 Tier 1 上检出率可观，Tier 3 上普遍低于 0.20。（4）**来源可用性而非方法差异主导实测结果**：DBLP 反爬拦截、OpenReview 返回 403、Semantic Scholar 无密钥限流 10 次/分钟，多来源方法的名义优势无法实现。复现研究因此必须把"来源条件"与准确率并列报告。

**关键词**：引用幻觉；文献真实性核验；基准复现；评测协议；来源可用性

## 1 引言

### 1.1 研究背景

学术写作依赖引用把论断锚定到既有证据，其前提是所引作品真实存在且字段准确；大语言模型进入写作流程后，这一前提大规模失效。GhostCite 以 13 个模型、40 个计算机子领域为抽样框架生成 331,809 条引用，测得幻觉率从 14.23%（DeepSeek）到 94.93%（Hunyuan），且由 2000 年的 27.61% 升至 2025 年的 98.75%^[1]^。Phantom References 的审计更具冲击力：48,095 篇已录用论文、2,614,992 条引用中，采用最保守的"身份层"定义（仅计完全虚构与作者身份严重损坏）后，2025 年 NeurIPS 与 USENIX Security 仍各有约 5% 的论文含两条以上伪造引用，而受影响论文与干净论文的平均审稿评分差仅 +0.02 到 +0.04^[2]^。

面对这一风险，检测工具与评测基准迅速涌现：HALLMARK、CiteAudit、CiteTracer、GhostCite 的 CiteVerifier、Phantom References 的 RefChecker、HalluCiteChecker 均在 2026 年前后发布^[1,2,3,4,5,6]^，方法论差异很大：有的只做标题可追踪性核对，有的做 12 码字段级裁决，有的把规则工具与大模型智能体级联。基准亦分化：HALLMARK 有 2,526 条带 14 类错误标注的 BibTeX 条目，CiteAudit 有 9,442 条引用，CiteTracer 有 2,450 条合成样本加 957 条真实场景样本^[3,4,5]^。

### 1.2 研究问题

工具与基准的丰富不等于结论的可靠。HALLMARK 作者列出三项自陈局限：规则工具与分类体系共同设计，级联分数只能视为上界；多数幻觉条目是合成扰动；核心划分仅覆盖英文 BibTeX 与五个机器学习会议^[3]^。这指向一个更基础的问题：**在这个任务上，什么程度的"复现成功"是可能的？**

本文不复现某篇论文的某个分数，而围绕四个问题组织实验：

**Q1（复现一致性）**：同一数据划分与评分脚本下，确定性基线的指标能否复现仓库发布的参考结果？差异来自方法、来源还是环境？

**Q2（子测试诊断能力）**：六个子测试各自对哪类错误有信号、作为独立检测器表现如何？需在真实来源上重新推导时，与标注的一致率是多少——即**标注本身的可复现性上界在哪里**？

**Q3（单阶段与多来源的权衡）**：DOI 解析、标题匹配与多来源级联三者在检出率、假阳性率与 API 成本上关系如何？

**Q4（不确定性与泛化）**：拒答条目在不同计分立场下影响多大？同一方法在真实世界来源与 LLM 生成来源的样本上是否一致？

### 1.3 本文贡献

1. 在固定环境与数据版本下复现 HALLMARK 确定性基线，**逐指标**核对与发布参考值的一致性，其中 `doi_only` 逐项一致。
2. 设计并执行一项**标注可复现性实验**：在冻结的分层子样本上从原始来源重新推导六个子测试，量化"标注层面"与"实测层面"的落差及其系统性缺口。
3. 系统记录复现过程中的**来源可用性条件**（DBLP 反爬拦截、OpenReview 403、Semantic Scholar 无密钥限流），论证来源条件必须与准确率一并报告。
4. 抽取并逐一分析 16 个代表性案例，覆盖检索失败、实体匹配错误、证据漏检与支持关系误判等错误来源。

## 2 相关工作

本项目的调研报告已梳理该方向的 19 项工作与 11 个数据集，此处只交代三条直接相关的脉络。

**书目真实性核验**按裁决粒度分三类：仅标题可追踪性（GhostCite 的 CiteVerifier 只回答"这篇作品能否找到"，作者承认是保守下界）^[1]^；字段级裁决（CiteTracer，12 码裁决并保留 Potential 中间态）^[5]^；保守身份层审计（Phantom References 的 RefChecker 只计完全虚构与作者身份严重损坏）^[2]^。HALLMARK 属第二类^[3]^。

**证据对齐**最贴近真实场景的资源是 Citation-Integrity（3,063 条真实生物医学引用、人工标注、按被引论文分组划分）；SemanticCite 扩展到全文四分类，SciCiteVal 提供细粒度错误分类，RefVerifier 把文献获取覆盖率作为一等指标报告（开放获取全文解析率仅 57.6%）^[7,8,9,10]^。作为可迁移的组件，SciFact 与 MultiVerS 奠定了"检索证据句 + 判定支持关系"的范式^[11,12,13,14]^，而科学事实核验的任务体系与工具能力边界可参考综述与工具评估^[15,16]^。

**评测学层面的既有认识**主要来自各论文的自陈局限：HALLMARK 的三项自陈限制已见前文，Phantom References 则承认其人工复核的 flag 中"多数不是幻觉"^[2]^。

本文不提出新的检测方法，定位是评测学层面的复现研究：检验已发布基准的标注、基线与实测行为的一致性。

## 3 复现对象与评测协议

### 3.1 任务定义与标签体系

HALLMARK 的输入是一条 BibTeX 条目，输出是 VALID / HALLUCINATED（允许 UNCERTAIN 拒答）的二分类判定与置信度^[3]^，可选附带预测的幻觉类型；标签体系为 14 种类型、3 个难度层：

- **Tier 1（易）**：`fabricated_doi`、`nonexistent_venue`、`placeholder_authors`、`future_date`——单次 API 查询或本地规则即可识别；
- **Tier 2（中）**：`chimeric_title`、`wrong_venue`、`swapped_authors`、`preprint_as_published`、`hybrid_fabrication`、`merged_citation`、`partial_author_list`——需要跨字段交叉核对；
- **Tier 3（难）**：`near_miss_title`、`plausible_fabrication`、`arxiv_version_mismatch`——需要深度核验或语义推理。

其中 `hybrid_fabrication` 尤其值得注意：DOI 真实且可解析，但标题或作者与 DOI 指向的作品不匹配，纯 DOI 检查下完全不可见^[3]^。

### 3.2 六个子测试

HALLMARK 的设计特色是把每条目分解为六个可独立回答的子问题：DOI 能否解析（`doi_resolves`）、标题是否存在（`title_exists`）、作者是否一致（`authors_match`）、场所是否正确（`venue_correct`）、字段是否完整（`fields_complete`）、跨库是否一致（`cross_db_agreement`）。每个子测试返回 True / False / N/A 三值，N/A 表示"不适用"，**既不能读作通过也不能读作失败**；子测试结果指出问题类别，且单个子测试即一个检测器，构成天然的消融框架^[3]^。

### 3.3 数据库优先级联

论文的主推架构是 `cascade_db_diagnosis`：第一阶段用规则工具 `bibtex-updater`（命令行工具 `bibtex-check`）查询 CrossRef、DBLP、DataCite、OpenAlex、Semantic Scholar 与 OpenReview，只把无法确定的条目交给第二阶段的 LLM 智能体。作者报告该级联在 `dev_public` 上取得 DR 0.996 / FPR 0.108 / F1 0.947 / Tier 加权 F1 0.800，在 `test_public` 上取得 DR 0.990 / FPR 0.112 / F1 0.957 / Tier 加权 F1 0.834^[3]^。

### 3.4 评价指标与两种计分立场

评测脚本提供两类指标。**分类指标**：检出率（幻觉类召回）、假阳性率（真实条目被误报的比例）、幻觉类 F1、Tier 加权 F1（仅召回按难度层加权，假阳性权重恒为 1）、MCC、AUROC、ECE；**覆盖与成本指标**：覆盖率、拒答数、平均 API 调用次数。

关键协议细节是**拒答如何计分**：保守模式（conservative）把 UNCERTAIN 排除在混淆矩阵之外，必须同时报告覆盖率；激进模式（aggressive）把 UNCERTAIN 与缺失预测按 HALLUCINATED@0.55 处理，即"数据库即金标准"立场。两者差值即论文所称的"数据库索引滞后税"，本文对第一阶段同时报告两种立场。

## 4 实验设置

### 4.1 数据与审计结果

复现使用 HALLMARK v1.2.4（构建日期 2026-10-15）。本文先审计发布文件本身，因为仓库 README 提示不同位置的统计口径存在差异，且早期 Hugging Face 镜像已随会议投稿撤回。

| 划分 | 条目数 | 真实 | 幻觉 | 幻觉率 | Tier 1/2/3 |
|---|---|---|---|---|---|
| `dev_public` | 1,119 | 504 | 615 | 0.5496 | 148 / 288 / 179 |
| `test_public` | 831 | 307 | 524 | 0.6306 | 128 / 243 / 153 |
| `stress_test` | 121 | 0 | 121 | 1.0000 | 0 / 85 / 36 |

审计确认三个划分的标签分布与版本元数据记录的数字**完全一致**（`dev_public` 504/615、`test_public` 307/524）；子测试金标准覆盖率 100%，完整性检查未发现缺失类型、缺失难度层或标签与类型不匹配的条目。

数据文件含若干**泄漏风险字段**（`label`、`hallucination_type`、`difficulty_tier`、`explanation`、`generation_method`、`source`、`subtests`、`raw_bibtex`）；其中 `subtests` 是逐条目子测试金标准，作为输入即构成答案泄漏，`explanation` 往往直接描述错误。评测流程通过上游 `BlindEntry` 机制只向基线传递 `bibtex_key`、`bibtex_type`、`fields` 与 `raw_bibtex`。

生成方式分布界定了结果边界：`test_public` 的 831 条中，扰动生成 361 条、抓取真实条目 287 条、LLM 生成 90 条、对抗构造 59 条、真实世界事件 34 条，即**多数正类是合成扰动**。

### 4.2 基线

| 基线 | 类型 | 依赖 | 说明 |
|---|---|---|---|
| `always_valid` / `always_hallucinated` | 常量参照 | 无 | 给出指标的平凡上下界 |
| `random` | 随机参照 | 无 | 固定种子 42，正类比例 0.5 |
| `doi_presence_heuristic` | 单字段启发式 | 无 | 无 DOI 即判幻觉 |
| `doi_only_no_prescreening` | 单来源 | doi.org | 仅检查 DOI 能否解析 |
| `doi_only` | 单来源 + 预筛 | doi.org | 上游默认配置，含本地预筛层 |
| `hallucitechecker` | 多来源标题匹配 | CrossRef / arXiv / S2 | Sakai et al. 2026 的移植版，阈值 0.9 |
| `checkifexist` | 多来源字段相似度 | CrossRef / S2 / OpenAlex | Abbonato 2026 算法 1 的移植版 |
| `bibtexupdater` | 规则工具 | 六个学术来源 | 级联的第一阶段 |
| `llm_zeroshot_*` | 大模型零样本 | LLM 网关 | 无工具、无检索 |

此外运行了 `title_oracle` 与 `venue_oracle` 两个**泄漏诊断基线**。它们把答案从带标签的参考池中查表得出，不是可部署的方法，用途是量化基准中可被捷径解出的部分。

### 4.3 环境与适配说明

**本节记录所有偏离上游默认配置之处，它们限定了结论的适用范围。**

**计算环境**：Windows 11，Python 3.11.5，NVIDIA MX570（2 GB 显存，未使用），所有实验在 CPU 上运行；HALLMARK 本身无 GPU 需求。

**软件版本**：HALLMARK 仓库提交 `80ce8ded`（2026-10-16），数据版本 v1.2.4，`bibtex-updater` 装于独立虚拟环境（依赖 `bibtexparser` 1.x，与 HALLMARK 要求的 2.x 冲突）。评测基准年份固定为 2026 以保证未来日期判定可重复。

**来源可用性（关键）**：复现环境的网络条件与作者运行环境存在实质差异，且**在单次会话内随时间变化**，实测如下：

| 来源 | 状态 | 实测证据 | 对结果的影响 |
|---|---|---|---|
| CrossRef | 可达但检索质量弱 | HTTP 200；按完整标题检索返回无关结果 | 标题匹配类方法的核心来源，其模糊检索质量构成方法上限 |
| OpenAlex | **配额耗尽（会话内恶化）** | 实验早期 HTTP 200（E3.2 子测试 160/180 成功）；后期 HTTP 429，报文为"Insufficient budget … free daily budget shared by everyone on your network's IP address, and that budget is used up ($0.0009 remaining; resets at midnight UTC)" | 多来源方法在会话后期退化为单来源 |
| DataCite | 正常 | HTTP 200 | 无 |
| arXiv | 正常（限速 20 次/分钟） | HTTP 200 | 限制吞吐 |
| Semantic Scholar | 限流 | 无密钥时 HTTP 429，上游默认配速 10 次/分钟 | 多来源方法吞吐受限，部分查询不完整 |
| **DBLP** | **被反爬拦截** | 所有 API 请求返回 HTTP 202 并附带 Anubis 挑战页（"Making sure you're not a bot!"），非 JSON 响应；180/180 失败 | 依赖 DBLP 的场所核验与跨库一致性不可用 |
| **OpenReview** | **被拒绝** | `api.openreview.net` 与 `api2.openreview.net` 均返回 HTTP 403 | 会议录用状态核验不可用 |

这一条件直接决定四件事：`bibtex-check` 在来源查询不完整条目超过 10% 时会以退出码 5 结束并拒绝评分，本文必须覆盖该门禁才能得到可评分的运行，故**所有第一阶段数字都标注为"来源不完整条件下测得"**；实时子测试在运行时只能访问 CrossRef 与 OpenAlex（DBLP 的 180 次查询全部失败）；多来源方法的名义优势无法实现，这是环境约束而非方法缺陷；**OpenAlex 的无密钥配额按出口 IP 全体共享，一次下午的评测即可耗尽**，随后依赖它的方法在同一会话内不可用，以免费接口为基础的评测协议因此不具备时间稳定性。

**来源退化导致的基线失效**：上述条件使 `checkifexist` 无法被有效测量——它按设计先查 CrossRef、仅在得分低时回退 Semantic Scholar 与 OpenAlex，而本次运行中 CrossRef 按完整标题检索返回无关结果（如对 SoftMatch 的标题返回"Trade-off between Quality and Cost"），两个回退来源又均返回 429，故其 `api_sources_queried` 只有 CrossRef 一项，300 条子样本输出全部为 HALLUCINATED（检出率 1.0000、假阳性率 1.0000）。**这不是该方法的性能，而是来源退化下的失效**，故不列入方法比较表，只作为"来源条件主导实测结果"的证据：检索失败与接口异常应与真实性、支持性结论分列记录。

**LLM 基线的模型替换**：上游 LLM 基线针对 GPT-5.1 / Claude Sonnet 4.6 / OpenRouter 系列模型发布，这些端点在本环境不可达；本文改用 OpenAI 兼容网关（`https://opencode.ai/zen/go/v1`）与 `deepseek-v4.1-flash` 模型，故**所有 LLM 数字都是替代模型下的适配实验，不是对已发布数值的复现**。

模型替换中发现一个必须记录的工程问题：该模型是重推理模型，默认 1024 token 预算下会把全部预算消耗在隐藏推理字段上，可见输出为空且 `finish_reason=length`，8 次调用中仅 1 次得到可用回复；预算提高到 8192 后 6 次全部成功。**推理模型在结构化判定任务上的可用性取决于输出预算而非模型能力**。

**级联的复现方式**：主推架构 `cascade_db_diagnosis` 分两阶段，端到端重跑需约四小时且绝大部分花在确定性的第一阶段；由于第一阶段给定磁盘缓存后是可重复的，本文**从已保存的第一阶段输出重建级联**：按上游 `ROUTE_TO_STAGE2` 状态集合（直接导入上游模块，避免词表漂移）把 831 条分为 627 条由第一阶段解决、204 条延迟到第二阶段，只对这 204 条运行第二阶段模型，再按上游规则合并。**路由与合并逻辑是上游的，第二阶段模型是替换的**，且使用零样本判定提示而非工具增强——第二阶段的工具正是本环境中退化的那些来源，给模型返回 429 的工具测的是故障而非方法。故级联数字同样是**适配结果**，与发布值并列报告而不作为其复现。

**子集使用**：Semantic Scholar 的 10 次/分钟配速使多来源基线的全量运行需约三小时，本文按课程要求对多来源基线（`hallucitechecker`、`checkifexist`、LLM 基线）使用**冻结的分层子样本**：按（标签，幻觉类型）比例分层，按 `bibtex_key` 排序后以固定种子 20261018 打乱抽取；子样本规模 300（多来源确定性基线）与 200（LLM 基线），单来源基线与第一阶段级联则在**完整划分**上运行。

### 4.4 可复现性措施

**公平比较**：所有基线使用同一划分与同一评分脚本（上游 `hallmark.evaluation.metrics.evaluate`），除待验证因素外设置一致；子样本对全部被比较的方法相同。

**防止信息泄漏**：只向基线传递 `BlindEntry`；不使用数据文件中的历史预测；子样本规则在模型输出产生前冻结。

**保留原始结果**：逐条目预测、评分结果与运行日志分别写入 `results/predictions/`、`results/metrics/` 与 `logs/`；每个指标文件附带 manifest，记录上游提交号、划分文件 SHA-256、运行时间戳与 API 调用总数。

**如实报告失败与随机性**：执行器逐条目做错误隔离，重试耗尽后记为拒答（`UNCERTAIN`，`evaluated=False`）并继续运行，拒答数单独计数；随机基线固定种子 42，子样本固定种子 20261018。

**观察五：零样本 LLM 显著领先，但需谨慎解读。** `llm_zeroshot` 在 200 条子样本上取得检出率 0.8559、假阳性率 0.0694、F1 0.9005、MCC 0.7717，全面优于所有确定性基线，平均只调用 1 次 API，覆盖率 0.915（17 条因响应解析失败记为拒答）；该模型**未使用任何检索工具**，判断完全依赖参数化知识，优势本质上来自"记住了哪些论文存在"而非核验能力——HALLMARK 作者的时间鲁棒性实验支持这一解读：2024–2025 年的新文献上 12 个 LLM 中有 8 个严重过报，最高假阳性率约 0.89^[3]^。但子样本仅 200、置信区间较宽，且这是替代模型下的适配结果，不是对已发布 LLM 基线的复现。

### 5.3 难度层分解：难度是相对于方法定义的

**表 3　各方法按难度层的检出率（`test_public`）**

| 方法 | Tier 1（易） | Tier 2（中） | Tier 3（难） | 难度走向 |
|---|---|---|---|---|
| `doi_only` | 0.5469 | 0.0741 | 0.0719 | 递减（符合设计） |
| `llm_zeroshot` | 0.8929 | 0.8302 | 0.8667 | 平坦 |
| `hallucitechecker` | 0.2222 | 0.3295 | **0.7091** | **递增（倒挂）** |
| `doi_presence_heuristic` | 0.3906 | 0.4979 | **0.6732** | **递增（倒挂）** |

表 3 呈现一个与基准设计意图相悖的现象：**四种方法中有两种的难度走向与 Tier 编号完全相反**。`doi_only` 符合设计预期——Tier 1 检出率 0.5469，Tier 2、3 骤降至 0.07 量级，因为 Tier 1 的四类错误（伪造 DOI、未来日期等）在字段层面即可见；而 `hallucitechecker` 与 `doi_presence_heuristic` 的检出率随 Tier 编号**上升**，在"最难"的 Tier 3 上反而最高（0.7091 与 0.6732）。这不是实现错误，而是**难度层定义与方法能力不匹配**：难度层相对于**字段级核验策略**定义，Tier 1 的错误字段层面即可见故"容易"，Tier 3 的错误（近似标题、貌似可信的伪造）字段层面完全正常、须深度核验故"困难"；而 `hallucitechecker` 是**纯标题匹配**方法^[6]^，对它而言 `plausible_fabrication`（论文不存在）的检出率是 1.000，`chimeric_title`（标题由多篇真实作品拼接）也是 1.000，而 `swapped_authors` 只有 0.087、`nonexistent_venue` 只有 0.154、`fabricated_doi` 与 `future_date` 都只有 0.200；`doi_presence_heuristic` 同理，它只检查 DOI 字段是否存在，而 Tier 3 的伪造条目更可能整条缺失 DOI，于是"最难"的层恰好是它最容易命中的层。

**结论是：难度层不是方法的固有属性，而是"方法 × 错误类型"的联合属性。** 用 Tier 指标比较工具时必须先说明能力范围，否则 Tier 加权 F1 会把"只做标题匹配"的方法误评为"在困难样本上表现更好"。

相比之下 `llm_zeroshot` 的三层检出率几乎平坦（0.8929 / 0.8302 / 0.8667），这不意味着 LLM 对困难样本有特殊能力，而是**基于参数化知识的判断不受检索式难度分层的影响**——它"记得"或"不记得"某篇论文。

在 `test_public` 的 180 条分层子样本上，本文用原始来源（CrossRef、OpenAlex、DBLP）重新推导六个子测试，并调用上游 `hallmark.evaluation.subtests` 的同名函数以保证逻辑一致。

**表 5　实时推导的子测试与发布标注的一致率（n = 180）**

| 子测试 | 可比条目数 | 一致率 | 实时弃权数 | 标注弃权数 |
|---|---|---|---|---|
| `fields_complete` | 180 | **0.9667** | 0 | 0 |
| `title_exists` | 180 | 0.8444 | 0 | 0 |
| `doi_resolves` | 55 | 0.6909 | 125 | 100 |
| `authors_match` | 164 | 0.6402 | 16 | 0 |
| `cross_db_agreement` | 160 | 0.5687 | 20 | 0 |
| `venue_correct` | 128 | **0.2266** | 52 | 0 |

该表是本文最重要的发现之一：**同一套判定逻辑、同一批条目，仅因元数据来源不同，一致率即可从 0.97 跌到 0.23**；`cross_db_agreement` 在标注层面信息量最高（F1 = 0.9831），实测层面一致率却只有 0.5687。逐项看：

`fields_complete` 一致率 0.9667 最高且完全离线（只查字段是否齐全、年份四位数字、DOI 是否合乎 `10.\d{4,}` 格式），是唯一"标注即事实"的子测试，剩余 3.3% 不一致来自模糊边界。

`title_exists` 一致率 0.8444，用 RapidFuzz 的 `token_sort_ratio`、阈值 0.90 判定；不一致集中在**近似标题**（`near_miss_title`），相似度跨越 0.90 阈值即翻转。

`authors_match` 一致率 0.6402（Jaccard 相似度、阈值 0.80）；不一致来自检索记录版本不同与姓氏提取在复姓、连字符、非拉丁姓名上的脆弱。

`cross_db_agreement` 一致率 0.5687，要求至少两个来源都有结果（来源间标题一致性阈值 0.85）；CrossRef 在 180 条上全部返回、OpenAlex 在 160 条上返回而 **DBLP 在 180 条上全部失败**（反爬拦截），故只剩两个来源、恰处于该子测试要求的边界，任一方缺失即弃权——**低一致率主要是来源缺失的直接后果**。

`doi_resolves` 一致率 0.6909，更值得注意的是**弃权规模**：180 条中 125 条实时推导返回 N/A（其中 100 条在标注中也是 N/A），只有 55 条可比——**覆盖率只有 31% 时，0.69 的一致率描述的只是很小的子集**。

`venue_correct` 一致率 0.2266 为最低：该子测试优先用"已知场所列表"（`known_venues`）模糊匹配、无列表时回退 API 场所字段，而场所名称表达差异极大（"NeurIPS" / "NeurIPS 2022" 等形式），单靠 `token_sort_ratio` 阈值 0.70 无法稳定判定，且标注时的场所注册表（很可能来自 DBLP，而 DBLP 不可用）与 API 字段并非同一信息源。**来源不可用与判定逻辑脆弱两个原因无法分离，这是本实验的一个已知局限。**

把实时推导的六个子测试按"任一失败即判幻觉"合并，在同一 180 条子样本上得到：

**表 6　实时子测试检测器与标注层面的对照（同一 180 条子样本）**

| 指标 | 实测层面 | 标注层面（同子样本） |
|---|---|---|
| 真阳性 | 113 | 114 |
| 假阳性 | 65 | 8 |
| 真阴性 | 1 | 58 |
| 假阴性 | 1 | 0 |
| 精确率 | 0.6348 | 0.9344 |

| F1 | 0.7740 | 0.9661 |

召回率 0.9912 与标注层面一致，未损失召回；但**假阳性率 0.9848 意味着 66 条真实引用中有 65 条被判为幻觉**，行为退化为"几乎全部报警"，F1（0.7740）与全判幻觉参照（0.7734）几乎相同。

这是本文对 Q2 的回答：**子测试分解在标注层面诊断能力极强（F1 = 0.971），实测层面却因元数据获取与模糊匹配的脆弱而无法兑现（F1 = 0.774，与常量分类器持平）**；缺口不在分解思想，而在各子测试背后的来源与阈值。

实测层面的假阳性集中在 `venue_correct`（52 条弃权、一致率 0.2266）、`cross_db_agreement`（20 条弃权，真实引用上大量返回 False 或 N/A）与 `authors_match`（版本差异）三个子测试——**误报的根源不是"没有找到证据"，而是"找到了不同版本的证据后按过严的规则判为不一致"**，与 Phantom References 作者的报告一致：人工复核发现假阳性主要来自"把编辑当作合著者""两篇真实论文同题冲突"等实体匹配问题^[2]^。

### 5.5 来源条件对实测结果的主导作用

前节结果指向一个更一般的观察：**来源可用性对实测结果的影响大于方法差异**。四组证据：`cross_db_agreement` 与 `venue_correct` 的低一致率直接源于 DBLP 不可用（180/180 失败）与场所注册表缺失；`bibtex-check` 对 5 条抽样条目中的 3 条报告来源查询不完整，上游注释还记录了 2026-09-02 的网络中断——所有来源 DNS 解析失败，工具对连续 2,500 条引用返回 `not_found`^[3]^；HALLMARK 作者报告多来源方法的假阳性率约为纯规则工具的 9 倍，换底层模型后各项指标差异不超过 5 个百分点^[3]^；**`checkifexist` 在本环境中完全失效**——其回退来源（Semantic Scholar、OpenAlex）运行时均返回 429，`api_sources_queried` 只剩 CrossRef 一项，300 条子样本输出全部为 HALLUCINATED，而同一方法若在来源健康时运行，行为会完全不同。

最后一点揭示了免费学术接口的结构性属性：**OpenAlex 的无密钥配额按 IP 地址共享，报文明确说明"free daily budget shared by everyone on your network's IP address"，实测剩余额度仅 $0.0009、需等到 UTC 午夜重置**——该资源是"每个出口 IP 一份"而非"每人一份"，共享网络或高并发评测下极易耗尽。本项目的 E3.2 子测试实验在会话早期还能成功查询 OpenAlex（160/180 条），数小时后同一端点在 `checkifexist` 运行中已完全不可用：**同一份代码、同一天、同一台机器，仅因时间不同而得到不同的可测性**。

因此本文主张：复现研究应把**来源条件**作为与准确率并列的一等报告项，至少记录来源可达性与响应状态、查询不完整条目比例、失败来源的报文，以及来源失败与真实"未找到"的区分方式。HALLMARK 仓库即提供了良好范例（逐条目 `coverage_incomplete` 标志、批次级健康检查、来源中断时拒绝评分），本文正是通过它的告警才发现 DBLP 已被反爬拦截。

### 5.6 第一阶段复现：工作点偏移而非判别力下降

Stage 1（`bibtexupdater`）在完整 `test_public` 上运行完成，可与仓库发布的参考值逐指标比对。

**表 7　Stage 1 的复现结果与发布参考值比对（`test_public`）**

| 指标 | 发布值 | 本文复现值 | 绝对差 |
|---|---|---|---|
| 检出率 | 0.8359 | 0.9848 | +0.1489 |
| 假阳性率 | 0.0717 | 0.3090 | +0.2373 |
| 幻觉类 F1 | 0.8902 | 0.9087 | +0.0185 |
| Tier 加权 F1 | 0.9050 | 0.9442 | +0.0392 |
| **MCC** | **0.7420** | **0.7387** | **−0.0033** |
| AUROC | 0.9200 | 0.8009 | −0.1191 |
| ECE | 0.3272 | 0.2027 | −0.1245 |

这张表是本文最值得讨论的复现结果。检出率与假阳性率都**大幅高于**发布值（+0.149 与 +0.237），只看这两项会得出"复现失败"的结论；但 **MCC 几乎完全相同（0.7387 对 0.7420，差 0.003）**，说明该工具在两组条件下的**整体判别力没有变化，变化的是工作点**：发布值对应来源健康的运行，工具能**肯定地确认**相当比例的真实引用；本次运行中 DBLP 与 OpenReview 全程不可用、Semantic Scholar 与 OpenAlex 大量 429，**肯定性确认能力被削弱**，于是把更多条目归入"发现不匹配"或"无法确认"而报警。逐条目状态分布给出直接证据：

**表 8　Stage 1 的逐条目状态分布（`test_public`）**

| 状态 | 条数 | 占比 |
|---|---|---|
| `verified`（肯定确认为真） | 167 | 20.1% |
| `title_mismatch` | 164 | 19.7% |
| `api_error`（传输失败） | 131 | 15.8% |
| `author_mismatch` | 104 | 12.5% |
| `unconfirmed` | 73 | 8.8% |

上游代码注释记载**健康运行的 `verified` 占比约为 52%、`not_found` 为 1–3%**^[3]^，本次运行 `verified` 仅 20.1%，另有 204 条（24.6%）因来源查询不完整被标记为 `coverage_incomplete`，量化了来源缺失的程度。故结论不是"复现失败"，而是：**同一工具、同一数据、同一评分脚本，在来源退化条件下会移动到更激进的工作点——用假阳性率换取检出率，而 MCC 这一综合判别指标保持不变。** 这也解释了 AUROC 为何下降 0.119：工作点偏移使置信度排序与真值的对应关系变差，但分类阈值附近的得失相互抵消。

### 5.7 拒答计分立场的影响

Stage 1 在保守与激进两种计分立场下的结果如下（覆盖率均为 0.755，即 204 条弃权）。

**表 9　拒答计分立场对 Stage 1 指标的影响**

| 指标 | 保守 conservative | 激进 aggressive | 差 |
|---|---|---|---|
| 检出率 | 0.9848 | 0.9885 | +0.0037 |
| 假阳性率 | 0.3090 | 0.4756 | +0.1666 |
| 幻觉类 F1 | 0.9087 | 0.8721 | −0.0366 |
| Tier 加权 F1 | 0.9442 | 0.9279 | −0.0163 |
| MCC | 0.7387 | 0.6179 | −0.1208 |
| AUROC | 0.8009 | 0.7300 | −0.0709 |

把 204 条弃权条目按"HALLUCINATED@0.55"处理，只换来检出率 +0.0037 的提升，代价是假阳性率 +0.1666、MCC −0.1208：**这是一个明显不划算的交易**，在本环境下，"数据库未能确认即判为伪造"的立场会损失超过一半的判别力。该结果与 HALLMARK 作者报告的权衡方向一致（激进模式提升 Tier 3 F1 但推高 FPR），但本文环境下的代价更大，因为来源缺失使弃权条目远多于健康运行，而其中包含大量真实引用。这为"拒答条目必须单独报告而非折叠"提供了量化依据。

### 5.8 级联的贡献是覆盖率而非准确率

按 4.3 节所述方式重建级联（627 条由第一阶段解决，204 条延迟到第二阶段，第二阶段用替代模型），得到下表。

**表 10　级联与第一阶段的对照（`test_public`）**

| 指标 | Stage 1 单独 | 级联（保守） | 级联（激进） | 发布值（级联，保守） |
|---|---|---|---|---|
| 检出率 | 0.9848 | 0.9531 | 0.9542 | 0.9900 |
| 假阳性率 | 0.3090 | 0.2614 | 0.2638 | 0.1120 |
| 幻觉类 F1 | 0.9087 | 0.9037 | 0.9050 | 0.9570 |
| Tier 加权 F1 | 0.9442 | 0.9336 | 0.9349 | 0.8340 |
| MCC | 0.7387 | 0.7265 | 0.7265 | — |
| AUROC | 0.8009 | 0.8320 | 0.8295 | 0.9510 |
| **覆盖率** | 0.7545 | **0.9844** | **1.0000** | — |

三点值得展开。

**第一，级联的主要收益是覆盖率，而非准确率。** 它把弃权条目从 204 条（24.6%）压缩到 13 条（1.6%），覆盖率从 0.7545 提升到 0.9844。与此同时 MCC 从 0.7387 微降到 0.7265（−0.012），幻觉类 F1 从 0.9087 微降到 0.9037。也就是说，**第二阶段的 204 次判定整体上是"有信息但略弱于第一阶段"的**——它把一批原本无法判定的条目变成了可判定条目，代价是其中一部分判错。对实际部署而言这是净收益（一个能对 98% 输入给出答复的系统比只能处理 75% 的系统可用），但它说明级联的价值不能被表述为"提高了准确率"。

**第二，第二阶段修正了部分假阳性。** 假阳性率从 0.3090 降到 0.2614（−0.048），检出率从 0.9848 降到 0.9531（−0.032）。这一方向与 HALLMARK 作者的报告一致：他们指出级联第二阶段的 flag 中约 59% 属于"真实作品被描述错误"^[3]^，即第二阶段倾向于在真实作品上纠正第一阶段基于缺失证据的报警。本文的观察是同一现象的量化：**第二阶段的净效应是把一部分第一阶段的误报改判为真实**。

**第三，与发布值的差距主要仍在假阳性率。** 我们的级联 FPR 为 0.2614，发布值为 0.1120，差 0.149；而 Tier 加权 F1 反而更高（0.9336 对 0.8340）。这一模式与 5.6 节第一阶段的结果一致——来源退化把整个系统推向更激进的工作点，在困难样本上换来更高召回，代价是真实条目被更多误报。AUROC 的差距（0.8320 对 0.9510）则反映替代模型在置信度排序上不如原模型。

需要再次强调，本节的级联数字是**适配结果**：路由与合并逻辑取自上游，但第二阶段模型是替换的，且使用零样本判定而非工具增强（理由见 4.3 节）。

表 11 已经呈现一个规律：**没有一条基线在所有案例上正确，且不同基线的错误几乎不重叠**。下面选取六例展开归因。

### 6.1 案例一：真实引用被误报，根因是来源不可用

`FP-VALID-a337fdfa` 是经 DBLP 抓取核验的真实条目（Afchar、Guigue、Hennequin 的 ICML 2021 论文），无 DOI 字段。`doi_presence_heuristic` 因"无 DOI"判为幻觉（设计上的必然误报），`doi_only` 因无 DOI 可查而保守判为真实，`hallucitechecker` 在 CrossRef 与 arXiv 中检索标题、最高相似度仅 0.661（低于 0.90 阈值）而判为幻觉——**误报**。根因不在阈值而在来源覆盖：该文为 ICML 2021 会议论文，最可靠的索引源 DBLP 被反爬拦截（见 4.3 节），CrossRef 对会议论文收录不完整、arXiv 上亦无预印本，故该真实引用在"可用来源的并集"中根本不存在，**是纯粹由来源不可用导致的假阳性**：判定逻辑为"所有可查询来源都没找到 ⇒ 不存在"时，**来源集合的缺失会直接转化为假阳性**，无法通过调参消除。

### 6.2 案例二：混合伪造——只有 DOI 与元数据的交叉核对才能发现

`FN-hybrid_fabrication-e8e1379d`：标题与作者完全正确（Kaiming He 等人的 MAE，CVPR 2022），但 DOI `10.1109/CVPR52688.2022.01552` 指向另一篇论文——真实 DOI 是 `.01553`，**相差一位数字**。三条基线全部失败：`doi_presence_heuristic` 因有 DOI 判为真实；`doi_only` 返回"不确定"（该 DOI 在 doi.org 上重定向成功，但 IEEE 落地页对程序化访问返回 HTTP 202）；`hallucitechecker` 按标题匹配、相似度 1.000，判为真实。**该错误类型在结构上超出前两条基线的能力范围**——字段齐全且格式正确、DOI 真实存在、标题完全正确，唯一能发现它的方式是**解析 DOI 指向的元数据再与引用中的元数据比对**，上游代码亦承认此类型为"DOI 真实但其他元数据与目标不匹配"。可见"DOI 可解析"作为真实性证据是脆弱的：**可解析只证明该 DOI 已注册，不证明它指向被引的那篇作品。**

### 6.3 案例三：近似标题——阈值两侧的一线之差

`FN-near_miss_title-0cb3d100` 的标题被轻微篡改（"GPT V" 被替换为 "GPT Visual 1.5" 一类的小改动），DOI 为 `10.48550/arXiv.2602.12133v1`。`doi_only` 判为幻觉，理由是"DOI 在 doi.org 返回 HTTP 404"——判定正确，但**理由需要辨析**：arXiv 的 DataCite DOI 采用带版本号的形式（`arXiv.2602.12133v1`），只有不带版本号的形式（`arXiv.2602.12133`）能在 doi.org 解析，带版本号必然 404；本条预测未触发上游的版本后缀剥离归一化，可能是"因错误理由得到正确结论"——**只看标签正确率会掩盖"对的答案、错的理由"**。`hallucitechecker` 判为真实，理由是标题在 arXiv 中匹配成功、相似度 0.963，高于 0.90 阈值。**这是一次漏检，且完全由阈值决定**：篡改后的标题与真实标题的相似度为 0.963，只比阈值高 0.063；若阈值提高到 0.97，该案例会被正确检出，代价是更多真实引用被误报（见附录 B.2）。

### 6.4 案例四：伪造 DOI 但标题匹配恰好越过阈值

`FN-fabricated_doi-aa79e4b0` 的 DOI `10.88882/9q1cuf3v1s` 是伪造的，标题与作者均真实：`doi_only` 正确判为幻觉（DOI 在 doi.org 返回 404），`hallucitechecker` 却判为真实——它在 CrossRef 中找到了真实论文，相似度 0.909，**恰好越过 0.90 阈值 0.009**。与案例三对照可见阈值问题的两面性：**同一个 0.90 阈值，在案例三上放过了篡改的标题（0.963），在案例四上放过了伪造的 DOI（0.909）**——两次都因"标题太像"而判为真实，而正确答案都要求识别标题之外的字段。

案例五与案例六（`TP-hybrid_fabrication-a73d7564`、`FN-swapped_authors-a4820127`）的完整分析见附录 B。

### 6.5 案例小结

六例归因可归纳为三类失效机制：**来源缺失型**（案例一、案例六，后者见附录 B.2）——来源集合不完整直接转化为假阳性，无法通过调参缓解，只能靠报告来源条件或人工复核；**字段盲区型**（案例二、案例五，后者见附录 B.1）——方法只看部分字段，`hybrid_fabrication` 是其极端形式；**阈值敏感型**（案例三、案例四）——正确与错误样本的相似度分布存在重叠区，0.90 阈值在两侧各有失败案例，存在不可通过调参消除的上限。

本节的案例**不覆盖"支持关系误判"**：该任务属于论断—原文证据对齐，本项目限定在书目真实性核验（见 3.1 节与 7.2 节），需要另一套数据与指标。

## 7 讨论

### 7.1 主要发现

**发现一：确定性基线可以精确复现，这使偏离可归因。** `doi_only` 在 `dev_public` 上七项指标逐项一致、`test_public` 上仅两个校准类指标有 0.001 量级差异。

**发现二：基准的标注自洽性高，但标注的可实测性低。** 标注层面"任一子测试失败"的 F1 为 0.971、实测层面为 0.774，后者与常量分类器持平。

**发现三：来源退化移动工作点，但不改变综合判别力。** Stage 1 的检出率与假阳性率都大幅高于发布值（+0.149 与 +0.237），而 MCC 几乎相同（0.7387 对 0.7420）。这说明"复现是否成功"不能只看检出率或 F1——同一工具在来源退化下只是移向更激进的阈值，用误报换召回，其判别力本身并未下降。**报告复现结果时应同时给出 MCC 一类的工作点无关指标**，否则会把工作点偏移误读为方法失效。

**发现四：级联的价值在覆盖率，不在准确率。** 重建的级联把弃权条目从 204 条压到 13 条（覆盖率 0.7545 → 0.9844），而 MCC 从 0.7387 微降到 0.7265。它让系统能对 98% 的输入给出答复，但没有提升判别力——把级联的收益表述为"提高了准确率"是不准确的。

**发现五：幻觉类 F1 在本任务上是误导性指标。** 全判幻觉在 `test_public` 上取得 F1 0.7734、Tier 加权 F1 0.8748，高于除级联外的多数真实方法，故只报告 F1 会事实上奖励"多报警"策略；必须联合报告假阳性率与 MCC。

**发现六：来源可用性主导实测结果。** DBLP 反爬拦截、OpenReview 403、Semantic Scholar 限流、OpenAlex 共享配额耗尽，使多来源方法无法实现名义优势——这是**部署场景的真实约束**。其中 OpenAlex 的配额按出口 IP 共享，本项目的实验在单次会话内即观察到它从可用转为不可用，说明以免费接口为基础的评测协议不具备时间稳定性。

**发现七：推理模型的可用性取决于输出预算。** `deepseek-v4.1-flash` 在 1024 token 预算下 8 次调用中仅 1 次产出可解析结果，8192 预算下 6 次全部成功。

**发现八：难度层是"方法 × 错误类型"的联合属性，不是方法的固有属性。** `hallucitechecker` 在 Tier 1 上检出率 0.2222、Tier 3 上 0.7091，与基准设计的难度走向完全相反——因为它只检查标题，而"论文不存在"（Tier 3）对它容易、"字段错误"（Tier 1）对它困难。

### 7.2 有效性威胁

**构造效度**。实测子测试使用自行实现的元数据获取逻辑（CrossRef + OpenAlex 直连）而非 `bibtex-check` 的内部路径，故 5.4.2 节的一致率既含标注的不稳定性，也含获取逻辑的实现差异；DBLP 不可用使 `venue_correct` 与 `cross_db_agreement` 的低一致率无法在"来源不可用"与"判定逻辑脆弱"之间归因。

**外部效度**。多来源与 LLM 基线使用子样本（300 与 200 条），指标与全量划分不可直接比较且置信区间更宽；所有 LLM 结果来自单一替代模型与单一网关，第一阶段数字在来源不完整条件下测得，均不可与已发布数值直接比较。

**内部效度**。条目级失败被隔离并记为拒答，避免整轮中断，但部分条目在重试耗尽后被排除；拒答数已单独计数，覆盖率在报告中给出。DOI 解析的不确定性（约 42%）是环境相关量。

**结论效度**。本文使用上游评分脚本与指标定义，未修改评价逻辑；Tier 加权 F1 的权重与 ECE 分箱方式均沿用上游实现。

### 7.3 对部署的启示

**本地预筛是纯收益**：`doi_only` 的预筛层不增加网络调用，把检出率从 0.1355 提升到 0.1889，假阳性率不变。

**不要把"未找到"当作"不存在"**：`bibtex-check` 的来源中断门禁与 DOI 检查遵循这一原则，而真实部署中常被简化为二值输出；Phantom References 作者报告其人工复核的 flag 中"多数不是幻觉"^[2]^，并指出"未发表作品与尚未被索引的作品无法区分"是结构性局限。

**报告覆盖率而非只报准确率**：系统对相当比例的输入选择拒答时，仅在已作答样本上计算准确率会产生选择偏差；本文实测中 `doi_resolves` 的覆盖率只有 31%。

**在目标流行率下重算精确率**：HALLMARK 作者报告在现实的约 2% 基率下，最好的工具每 6 至 10 个 flag 中才有 1 个真命中，最激进的工具低于 1/35^[3]^。

---

## 8 结论

本文以 HALLMARK 基准为对象完成了一次系统的复现与分析，主要结论是：**确定性方法可以被精确复现，而"可验证性"本身在真实网络条件下会被显著削弱**。`doi_only` 的七项指标在 `dev_public` 上与发布值逐项一致；子测试分解在标注层面达到 F1 = 0.971，实测层面仅 0.774；所有方法在 Tier 3 上接近失效；来源可用性（DBLP 被反爬拦截、OpenReview 403、Semantic Scholar 限流）的影响大于方法差异。

这些结论并不否定 HALLMARK 或同类工作——恰恰相反，正是其工程设计（逐条目子测试标注、来源中断时拒绝评分、公开的逐样本参考结果）使本文能定位问题所在：**该领域下一步的瓶颈可能不在判断模型的强弱，而在证据获取链条的可靠性**。

## 附录 B　完整案例集

### B.1 案例五：混合伪造被正确检出，但理由同样值得辨析

`TP-hybrid_fabrication-a73d7564` 同样是 `hybrid_fabrication`（真实 DOI `10.1109/CVPR52688.2022.00884`，但标题与作者被替换为虚构内容）。`hallucitechecker` 正确判为幻觉，理由是"标题在 CrossRef 与 arXiv 中均无匹配，最高相似度 0.764"。

判定正确，但**理由与错误类型不匹配**：工具是因为"标题查不到"而报警，而真实错误是"DOI 与元数据不匹配"。如果这条引用的标题恰好是真实的、只是作者被替换，工具就会漏检（如案例二）。因此这次成功是**标题恰好也被替换**这一偶然因素的结果，而非方法覆盖了该错误类型。

这与 HALLMARK 作者报告的一个现象一致：在真实语料上，级联第二阶段维持的 flag 中有 59.0% 属于"真实作品被描述错误"，即工具报警了但归因往往不对。

### B.2 案例六：真实世界事件中的作者错配——标题匹配的结构性盲区

`FN-swapped_authors-a4820127` 不是合成扰动，而是来自真实事件：GPTZero 在 NeurIPS 2025 已录用论文中发现的问题引用。标题"SoftMatch: Addressing the quantity-quality trade-off in semi-supervised learning"完全正确（真实论文发表于 ICLR 2023），但作者被整体替换为四个虚构姓名（Junyeong Lee、Yiseong Kim、Seungju Park、Hyunjik Lee）。

`hallucitechecker` 判为真实，理由是"标题在 arXiv 中匹配成功，相似度 1.000"。`doi_only` 因无 DOI 字段而保守判为真实。**两条基线全部漏检，且这是它们能力范围内的必然结果**：标题是唯一被检查的字段，而标题恰恰完全正确。

这条案例与案例二（MAE 的 DOI 错配）构成一对互补的证据：**同一个错误家族（字段层错误）在标题字段上不可见，在 DOI 字段上也不可见，但原因不同**——案例二的问题是"检查了 DOI 却没有核对 DOI 指向的内容"，本案例的问题是"根本没有检查作者字段"。两者共同指向同一个结论：**任何只检查部分字段的方法，都会在其未检查的字段上系统性失效，且这种失效不表现为随机错误而是完全漏检**。

值得注意的是这条案例的来源：它是**真实世界中已经通过同行评审的错误引用**。GhostCite 的档案审计发现，2025 年含此类错误引用的论文比例相比 2020–2024 年均值增长了 80.9%[GhostCite]；Phantom References 则发现受影响论文与干净论文的审稿评分几乎无差别[PhantomRef]。本案例表明，这类错误恰好落在现有自动化工具的盲区上。
